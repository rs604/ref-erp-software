Whether a challan was returnable is not a field in Busy. It was typed into the description in free words — "MATERIAL SEND FOR CUTTING", "SEND FOR REPAIRING", "TOOLS RETURNING BACK AFTER" — differently every time. So a pending-returnables list cannot honestly be built from this data. It is searchable though: type repairing to see every item ever sent out for repair.

GST — what was computed, and what was paid
Both figures come from the GST ledger itself. Paid is money that actually left the bank on a payment voucher. Computed is the monthly journal working out the liability. If the two drift apart over time, input credit is not all being claimed.

GST on invoices — estimate only
An estimate, not a bill. Some input credit is not eligible, and reversals, reverse charge and credit notes all change the figure. Your accountant works that out at filing. This screen does not know any of it, so it is never labelled payable. The figures above, from the GST ledger, are the real ones.
Why a 2018 invoice can never change.
Each sync compares only the years that are still on the office PC. Anything in those years that has gone from Busy is marked deleted here — the row is never removed. Once you take an old year off the PC it is frozen: kept here for good, never compared again, never touched. You keep the current year and the one before it, because late entries get posted into the previous year. So the older years simply stop changing, and nothing is lost.

The uploader for the office PC
One small program that sits on the accountant's PC and sends the Busy files up twice a day. It never opens Busy and never writes to it — it reads the files, the same as copying them.
Download the uploader
The upload token is a password. Anyone holding it can send files to the ERP. Keep it out of email, and if that PC is ever replaced or sold, change the token here first.
Written for somebody who has never seen this before — which in three years, with a new PC, may be you. Nothing here assumes you remember any of it.
Putting the uploader on a new PC
  1. Make a folder on that PC called C:\RefUploader
  2. Download the uploader from Busy Data ▸ Download the uploader and put RefBusyUploader.exe in that folder
  3. In the same folder make a text file called config.txt holding three lines: 
    busy_folder =
erp_url = (shown on the download screen)
upload_token = (shown on the download screen)
    Leave busy_folder empty the first time. The program looks in the usual places and writes in what it finds.
  4. Double-click the program once. Nothing will appear on screen — that is correct, it is meant to be silent. Check that a file called uploader.log turns up beside it, and that the last line is not a complaint
Making it run by itself
  1. Press the Windows key, type Task Scheduler, open it
  2. On the right, Create Task (not "Create Basic Task")
  3. General tab — name it REF Busy Upload. Tick Run whether user is logged on or not, so it works when nobody is sitting at the PC
  4. Triggers tab ▸ New ▸ Daily, start 6:00 AM. Tick Repeat task every 1 hour for 1 day
  5. Actions tab ▸ New ▸ Start a program. Program: C:\RefUploader\RefBusyUploader.exe. Start in: C:\RefUploader — this one matters, leave it out and it will not find its own settings file
  6. Conditions tab — untick Start the task only if the computer is on AC power, or it will skip on a laptop
  7. OK. Windows asks for the PC password, because of step 3
It runs every hour on purpose, but only does the work when the ERP says a run is due. That way the times are changed here, in the ERP, and nobody ever has to touch Task Scheduler again.
Pointing it at a different Busy folder
Open config.txt in Notepad and put the full path after busy_folder =, for example C:\BusyWin\Data. Save it. Nothing else to do — it is read on the next run.
If the data stops arriving
Every screen here shows "as at" and a time. If that time stops moving, work down this list:
  1. Is the office PC switched on, and does it have internet
  2. Open C:\RefUploader\uploader.log on that PC. The last line says what happened in plain words
  3. In Task Scheduler, find REF Busy Upload and look at Last Run Result. 0x0 means it ran fine
  4. Has Busy been moved or reinstalled? Then busy_folder in config.txt is pointing at a folder that is no longer there
  5. Was the PC replaced? Then start again from the top of this page
You should not have to watch for this. If the sync fails for the number of days set in settings, the ERP emails you — the point being that a sync which stops quietly is noticed, rather than found out the day a price is needed.
